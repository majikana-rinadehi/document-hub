
## 概要


巷をにぎわすOpenRouterにやっと触れ、Difyワークフローに適用してみたメモ


## OpenRouter とは

- 一つのAPIキーで複数のAIモデルを効率よく使えるプラットフォーム
    - 数百のモデルを切り替え可能、特定のモデルに偏らない中立さ
    - 多様なモデルのAPIインターフェースを統一、標準化
    - いろいろなモデルの状態をDashboardで比較・可視化
    - データ保持期間、学習拒否の設定も可
- 使い方
    - API
        - /api/v1/chat/completions を呼ぶだけ
    - Client SDKs
        - ライブラリ。コードから呼び出す場合
    - Agent SDK
        - より高度なSDK。複数ターン、ループ、会話の状態保存
- Creditsの設定が可能。なしでも使えるが、その場合無料のRate limitsによる制限/遅い
    - [https://openrouter.ai/docs/api_reference/limits#rate-limits](https://openrouter.ai/docs/api_reference/limits#rate-limits)

## 初期設定

- [https://openrouter.ai/](https://openrouter.ai/) でSignUp / APIキー設定 / 支払い情報登録
    - APIキーを控えておく
    - Creditsのチャージ画面が出てくるがskip可
    - →チャージなしの場合何回か使うとRate Limitで遅くなったので10$だけチャージ

## DifyのAPIキーに適用してみる

- Difyのモデルプロバイダー設定画面 > OpenRouter を選択
- OpenRouterで発行したAPIキーを設定
- ワークフローのAIモデルを、OpenRouterのものに差し替え
    - せっかくなので gemini 3.5 flash → deepseek v4 flash latest に
    - 日付付きのものは突然消える可能性あるので避ける
- 差し替え後、テスト実行が成功
    - 明らかにレスポンスが早くなった
    - OpenrouterのActicity / Logs などに詳細に使用ログが出る

## モデルの比較

- compare画面で複数モデルを比較可能
    - [https://openrouter.ai/compare/google/gemini-3.5-flash/~deepseek/deepseek-v4-flash-latest](https://openrouter.ai/compare/google/gemini-3.5-flash/~deepseek/deepseek-v4-flash-latest)

## まとめ

- OpenRouterを使えば1APIキーでいろいろなモデルを試し、簡単に比較できる
- Deepseek等、安価で高速なopenモデルに触れられる
- 様々なモデルの比較検討もしてみたい
